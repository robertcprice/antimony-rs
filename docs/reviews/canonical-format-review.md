## 1. What We Built (Plain English)

The native formatter validates a parsed model, gives it deterministic readable
layout, then reparses and checks the generated text before returning it. It retains
original non-trivia tokens and their order rather than rebuilding source from
normalized SBML metadata. A native-only file adapter writes output only after
validation succeeds. Fifteen independent reviewer tests complement twenty-six
implementation formatter/numeric-boundary tests.

## 2. Why It Matters (Impact & Implications)

Users can normalize supported Antimony without losing initialization mode, raw
unit-alias intent, ordering-sensitive generated definitions or operator binding.
This enables readable generated files and stable repeated formatting without
embedding Python or SBML in the formatter runtime.

### Actual API and canonicalization contract

`format_antimony(&ParsedDocument) -> Result<String, Diagnostic>` works without the
`sbml` feature. It analyzes the original document, emits bounded text, then parses
and analyzes that output using the retained limits. Invalid/unsupported input does
not receive a best-effort success string.

- Named/anonymous envelopes, statement/token order, numeric spellings, unary signs,
  explicit parentheses, reaction arrows/boundary markers and unit syntax remain.
  Literal initialization is not changed into an InitialAssignment or vice versa.
- Canonical layout uses LF, semicolon-terminated statements, two-space named-model
  indentation, and a reaction's participant/rate separator on the same line.
  Comments and original whitespace are intentionally removed. This is **not** a
  lossless editor or one canonical serialization of all semantically equivalent
  models. No sorting, simplification or algebraic reassociation is performed.
- Source-byte expansion is checked before appending. Actual generated token/depth
  limits are checked by reparsing. Resource failure returns no string. Diagnostics
  from generated text are remapped to a valid zero-width span in the original
  source; a reused source ID never exposes unrelated generated byte offsets.
- The CLI is `format_antimony INPUT.ant OUTPUT.ant`. Input reading is bounded.
  Output is staged in the destination directory and renamed only after successful
  validation/write. Rejected input leaves an existing output unchanged; failed
  writes clean temporary files. This is not a filesystem durability guarantee.
- Core parsing/formatting remains native, side-effect-free and independent of SBML,
  with privately constructed semantic state. Reference tools remain development-only.

### Baseline scalar defects found and fixed before approval

Independent original-versus-reference checks found that `a=1e-308` produced native
SBML rejected by libSBML (XML error 1016), while nonzero `1e-400` became zero in the
old scalar path. Near floating-point normal/max boundaries also had unverified
reference behavior. Separately, original source `a=1.234567890123456789` produced
native 1.2345678901234567 versus reference 1.23456789012346;
`a=1.0000000000000002` produced native 1.0000000000000002 versus reference 1.
Native self-roundtrip/idempotence alone did not expose these mismatches.

The authorized fix rejects instead of rounding or weakening the comparator:

- Scalar initialization (parameters/species/compartments) and stoichiometry allow
  exact zero or magnitude **[1e-307, 1e308]**, at most **15 significant mantissa
  digits**. Exponent digits and leading zeros do not count; trailing zeros after
  the first nonzero digit do count; an all-zero mantissa counts as zero digits.
- Nonzero textual mantissas that underflow to `f64` zero reject. Existing finite,
  positive compartment/stoichiometry and nonnegative species checks still apply.
  Signed zero and `0e-999` remain valid where zero is otherwise permitted.
- Existing arithmetic-expression and unit-coefficient envelopes remain tighter;
  expression underflow was already guarded and now has independent regressions.
- This is an explicitly stricter supported serialization envelope, not a claim that
  every excluded value is invalid Antimony. No clamping or guessed conversion.

## 5. Novel Opportunities (Innovation & Monetization)

A small native check/format/export pipeline can support editor integrations and
reproducible model preprocessing. Its useful distinction is auditable preservation
with explicit limitations, not unsupported full-language or scientific-validation
claims. No publication, licensing or commercialization action was taken.

## Key Learnings:

1. Native idempotence alone cannot establish upstream equivalence.
2. Source tokens preserve alias/initialization intent that normalized SBML cannot reconstruct safely.
3. Rejecting unverified scalar ranges/precision is safer than silently rounding to match an oracle.
